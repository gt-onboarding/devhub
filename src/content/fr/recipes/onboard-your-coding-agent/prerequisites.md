Ce modèle rend un dépôt Databricks prêt pour les agents : il installe la connaissance de la plateforme Databricks dans l&#39;agent de codage de l&#39;utilisateur, connecte le serveur MCP DevHub Docs et écrit un fichier `AGENTS.md` (accompagné d&#39;un `CLAUDE.md` en lien symbolique) qui fixe les valeurs par défaut du workspace dont les agents ont besoin pour agir correctement sur ce codebase.

* **Un dépôt dans lequel intégrer l&#39;agent.** Exécutez cette commande depuis la racine du projet sur lequel l&#39;agent travaillera. Si l&#39;utilisateur n&#39;a pas encore de projet, exécutez d&#39;abord [Créer une Databricks App](/templates/spin-up-databricks-app), puis revenez ici depuis le répertoire dont l&#39;ossature a été générée.
* **Un agent de codage installé localement.** L&#39;installateur Databricks aitools détecte Cursor, Claude Code, Codex CLI, OpenCode, GitHub Copilot et Antigravity. L&#39;installation du serveur MCP DevHub via `npx add-mcp` fonctionne avec les mêmes outils, plus VS Code.
* **`npx` disponible.** L&#39;installation du MCP DevHub passe par `npx add-mcp` — livré avec Node.js `18+`. Exécutez-le avec `--yes` pour que l&#39;installation reste non interactive lorsque votre agent la lance dans un shell sans interface.
* **La connaissance des ressources Databricks que ce dépôt utilisera.** Avant d&#39;écrire `AGENTS.md`, vous demanderez à l&#39;utilisateur quel profil CLI, quelle URL de workspace, quel catalogue/schema Unity Catalog, quel project/branch Lakebase, quel Genie Agent et quel endpoint Model Serving doivent servir de valeurs par défaut pour ce dépôt. Vous pouvez tout à fait laisser des champs vides avec un marqueur `TODO:` si l&#39;utilisateur ne le sait pas encore.
