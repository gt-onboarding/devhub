Ce modèle crée une table synchronisée qui réplique une table Unity Catalog dans Lakebase Postgres. Avant de commencer, vérifiez que ces fonctionnalités du workspace Databricks sont activées.

* **Lakebase Autoscaling disponible.** Exécutez `databricks postgres list-projects --profile <PROFILE>` et vérifiez que votre projet Autoscaling figure dans la liste. Une erreur `not enabled` signifie que Lakebase n&#39;est pas disponible pour cette identité.
* **CLI prenant en charge les tables synchronisées.** Sur les projets Autoscaling, les tables synchronisées se créent avec `databricks postgres create-synced-table` (bêta). Exécutez `databricks postgres create-synced-table --help` et vérifiez que la commande existe ; si ce n&#39;est pas le cas, mettez à niveau le CLI Databricks. Vous pouvez également créer des tables synchronisées depuis l&#39;interface Databricks (**Catalog** → table source → **Create synced table**).
* **Table source Unity Catalog.** Exécutez `databricks tables get <CATALOG>.<SCHEMA>.<SOURCE_TABLE> --profile <PROFILE>` et vérifiez que la source existe, puis déterminez la ou les colonnes qui serviront de clé primaire à la table synchronisée — vous les transmettez via `primary_key_columns` dans la spécification de création. La source n&#39;a pas besoin de contrainte de clé primaire déclarée.
* **Change Data Feed activé sur la table source (pour les modes Triggered / Continuous uniquement).** Ignorez cette vérification si vous prévoyez d&#39;utiliser le mode Snapshot. Sinon, exécutez sur votre SQL warehouse l&#39;instruction `ALTER TABLE <catalog>.<schema>.<table> SET TBLPROPERTIES (delta.enableChangeDataFeed = true);` de l&#39;étape 1.
