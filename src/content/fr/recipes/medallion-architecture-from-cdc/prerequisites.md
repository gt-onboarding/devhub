Ce modèle construit un Lakeflow Spark Declarative Pipeline s&#39;appuyant sur des tables d&#39;historique Lakebase Change Data Feed (CDF) existantes. Vérifiez que ces fonctionnalités du workspace Databricks sont activées avant de commencer.

* **Lakeflow Spark Declarative Pipelines (sans serveur) disponibles.** Exécutez `databricks pipelines list-pipelines --profile <PROFILE>` et vérifiez que la commande aboutit (une liste vide est normale). Une erreur de permission ou `not enabled` signifie que Lakeflow Pipelines n&#39;est pas disponible pour cette identité.
* **Accès à Unity Catalog avec un schema de destination accessible en écriture.** Exécutez `databricks catalogs list --profile <PROFILE>` et vérifiez que votre catalogue de destination figure dans la liste. Vous aurez besoin de `USE_CATALOG` sur le catalogue ainsi que de `USE_SCHEMA` + `CREATE_MATERIALIZED_VIEW` sur le schema de destination pour publier les materialized views silver et gold (et de `CREATE_TABLE` si le pipeline crée également des tables en streaming).
* **Tables d&#39;historique CDC bronze déjà présentes dans Unity Catalog.** Suivez d&#39;abord le modèle [Lakebase Change Data Feed (Autoscaling)](/templates/lakebase-change-data-feed-autoscaling) afin que les tables `lb_<entity>_history` existent dans le schema bronze. Ce modèle lit ces tables ; il ne les crée pas.
