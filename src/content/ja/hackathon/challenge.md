## プロンプト \{#prompt\}

インド全土の医療施設に関する、雑多な10,000件のレコードが与えられます。各レコードには、所在地や診療科などの構造化フィールドに加え、対応可能とされる診療能力・処置・設備・サービスについて、書式のばらついた自由記述の説明が含まれます。

技術者ではない医療プランナー、NGOのコーディネーター、アナリストが、この雑多なデータを信頼できる意思決定につなげられるよう支援するDatabricks Appを構築してください。

アプリはレコードから有用な構造を抽出し、結論の根拠を示し、不確実性を誠実に伝え、ユーザーが作業内容を保存・修正できるようにしてください。

## 基本要件 \{#core-requirements\}

提出物は次の条件を満たす必要があります。

* Free Edition 上で Databricks App として動作すること。
* 提供された施設データセットを使用すること。
* 技術者でないユーザーにも分かりやすいワークフローに対応すること。
* 重要な主張、推奨、スコア、ランキングには、根拠となる施設のテキストを引用すること。
* 根拠の乏しい情報を事実として示すのではなく、不確実性を明示すること。
* メモ、上書き設定、ショートリスト、シナリオ、レビュー判断といったユーザーの操作内容を永続化すること。

## データセット \{#dataset\}

提供されるデータセットには、インドの医療施設に関する10,000件のレコードと51のカラムが含まれています。

すべてのレコードに施設名、州、都市、緯度、経度、対応する診療科、説明、ソースURLが含まれ、9,996件のレコードには郵便番号も含まれています。抽出された根拠フィールドはノイズが多く、記述の重複があり、裏付けの度合いにもばらつきがあります。

| フィールド           | カバレッジ |
| --------------- | ----- |
| description     | 100%  |
| capability      | 99.7% |
| procedure       | 92.5% |
| equipment       | 77.0% |
| numberDoctors   | 36.4% |
| capacity        | 25.2% |
| yearEstablished | 47.8% |

有用な根拠は、description、capability、procedure、equipment、specialties、source&#95;urls の各フィールドに散在しています。各チームはこれらのフィールドを確定した事実としてではなく、検証すべき主張として扱ってください。

## トラックを1つ選択する \{#pick-one-track\}

### トラック1: 施設信頼性デスク \{#track-1-facility-trust-desk\}

問い: この施設は本当に主張どおりの対応ができるのか?

ICU、産科、救急、腫瘍科、外傷、NICUといった診療機能について、施設側の主張を評価するアプリを構築します。施設と機能の組み合わせごとに、強い根拠あり、部分的な根拠あり、根拠が弱い・疑わしい、主張なしといった信頼シグナルを出力します。

最小限のワークフロー: プランナーが機能と地域を選択し、ランク付けされた施設一覧を確認、施設を展開して引用元を精査し、メモを添えて評価を上書きできる。

### トラック2: 医療過疎地プランナー \{#track-2-medical-desert-planner\}

問い: 最もリスクの高い医療提供のギャップはどこにあり、そのギャップが実在するとどの程度確信できるか?

州・市・地区・郵便番号といった地理単位で、信頼度による重み付けを施した施設根拠を集約するアプリを構築します。実際の医療ギャップなのか、単にデータが乏しい地域なのかを、プランナーが見極められるように支援します。

最小限のワークフロー: プランナーが診療機能と地理を選択し、地域ごとのカバレッジを確認し、集計値の背後にある施設レコードまでドリルダウンし、計画シナリオを保存する。

### トラック3: 紹介コパイロット \{#track-3-referral-copilot\}

問い: 患者やコーディネーターは実際にどこへ行けばよいのか?

ユーザーが場所とケアのニーズ(たとえば「ジャイプール近郊の透析」「パトナ近郊の緊急手術」など)を入力すると、根拠付きの候補施設ショートリストが返ってくるアプリを構築します。

最小限のワークフロー: 場所とニーズを入力として受け取り、ランク付けされた候補を出力する。各候補には距離、一致する根拠、欠落または疑わしい根拠が表示され、ショートリストに保存できる。

### トラック4: データ整備デスク \{#track-4-data-readiness-desk\}

課題: このデータセットを計画に使えるだけの信頼性を得るには、何を修正する必要があるか？

施設データセットのプロファイリング、レビュー、改善を行うアプリを構築してください。矛盾、疑わしい記載、欠損の多いフィールド、影響度の高いレコードを洗い出し、人によるレビューに回します。

最低限のワークフロー: 完全性と品質の問題を可視化し、フラグ付きレコードのレビューキューを用意し、レビュー担当者の判断を後続工程で使えるよう永続化すること。
