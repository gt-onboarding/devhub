# Descripción general de la plataforma \{#platform-overview\}

Databricks Apps, Lakebase Postgres, Agent Bricks y el Data Lakehouse son los cuatro servicios principales del workspace que conforman una aplicación full-stack de Databricks. El siguiente diagrama muestra cómo se relacionan entre sí.

![Diagrama de arquitectura del workspace de Databricks: Databricks Apps contiene AppKit, cuyos plugins de Lakebase, Model Serving y Analytics se conectan a Lakebase, Agent Bricks y el Data Lakehouse como servicios hermanos dentro del workspace; una cuarta columna enumera plugins adicionales de AppKit (Server, Genie, Files, Jobs, Vector Search y plugins personalizados)](/img/docs/platform-overview.svg)

* **[Databricks Apps](/docs/apps/overview)**: hosting gestionado para las aplicaciones que desarrollas con [AppKit](/docs/appkit/v0), el SDK de TypeScript para crear aplicaciones de Databricks listas para producción.
* **[Lakebase Postgres](/docs/lakebase/overview)**: base de datos Postgres gestionada para almacenamiento OLTP, ubicada junto a los datos de tu workspace. Úsala para sesiones, estado de la aplicación, historial de conversaciones o cualquier dato que tu aplicación lea y escriba con baja latencia.
* **[Agent Bricks](/docs/agents/overview)**: la plataforma de agentes empresariales de Databricks, que unifica el acceso a modelos, la ejecución, la gobernanza y el contexto. Úsala para las funcionalidades de IA de tu aplicación: chatear con la documentación de tu empresa (Knowledge Assistants), consultar tus datos en lenguaje natural (Genie), llamadas a modelos fundacionales o agentes personalizados en Python.
* **[Data Lakehouse](/docs/lakehouse/overview)**: datos analíticos gobernados en Unity Catalog. Úsalo para leer datos de la empresa, ejecutar Lakeflow Jobs y mostrar la vigencia de los datos en tu interfaz.

## Cómo fluye una solicitud \{#how-a-request-flows\}

1. Un usuario abre la aplicación en su URL del workspace. Databricks Apps lo autentica mediante el SSO del workspace.
2. A continuación, cada plugin de AppKit atiende las solicitudes de su servicio: el Lakebase Plugin consulta Lakebase, el Model Serving Plugin llama a Agent Bricks y el Analytics Plugin lee el Data Lakehouse.
3. Cada llamada de un plugin se ejecuta con el service principal de la aplicación (de forma predeterminada) o con el token reenviado del usuario (cuando importan los permisos por usuario). Los permisos y la gobernanza del workspace se aplican automáticamente.
